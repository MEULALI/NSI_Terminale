Correction détaillée : La récursivité (Terminale NSI)

Question 1 — Pourquoi la première version échoue

def somme(n):
    return n + somme(n - 1)

Problème : il n’y a pas de cas de base (cas d’arrêt). La fonction s’appelle elle-même indéfiniment avec des valeurs décroissantes (n-1, n-2, … jusqu’à des entiers négatifs) sans jamais s’arrêter. Python interrompt alors l’exécution avec l’erreur :

RecursionError: maximum recursion depth exceeded

Chaque appel ajoute un cadre (frame) sur la pile d’appels ; la pile finit par dépasser la profondeur maximale autorisée (environ 1000 appels par défaut). C’est ce qu’on appelle une récursion infinie.

Question 2 — La version correcte

def somme(n):
    if n == 0:          # ← lignes 2 et 3
        return 0        # ← cas de base
    else:
        return n + somme(n - 1)
  • Les lignes qui résolvent le problème sont les lignes 2 et 3 : if n == 0: return 0.
  • Ce cas s’appelle le cas de base (ou cas d’arrêt / cas trivial) : il stoppe la descente des appels récursifs. Sans lui, la récursion ne termine jamais.

Déroulé de l’exécution (à montrer au tableau)

somme(4)
= 4 + somme(3)
= 4 + (3 + somme(2))
= 4 + (3 + (2 + somme(1)))
= 4 + (3 + (2 + (1 + somme(0))))
= 4 + (3 + (2 + (1 + 0)))      ← le cas de base renvoie 0
= 10

La descente s’arrête au cas de base, puis les résultats « remontent » (phase de dépliage / repliement).

Question 3 — La factorielle

⚠️ Attention : l’énoncé contient une coquille, fact(n) = n × fact(n) est circulaire. La bonne définition est fact(n) = n × fact(n−1), avec fact(1) = 1 (et par convention fact(0) = 1).

def fact(n):
    if n == 0 or n == 1:    # cas de base
        return 1
    else:
        return n * fact(n - 1)

Vérifications : fact(5) = 5×4×3×2×1 = 120, fact(0) = 1, fact(1) = 1.

Remarque de rigueur : cette version n’est pas robuste pour n < 0 (récursion infinie). Une version plus rigoureuse :

def fact(n):
    if n < 0:
        raise ValueError("n doit être positif")
    return 1 if n <= 1 else n * fact(n - 1)

Questions supplémentaires

Compréhension

  1. Citez les deux ingrédients obligatoires de toute fonction récursive.
  2. Que se passe-t-il en mémoire (pile d’appels) lors d’un appel récursif ?
  3. Que vaut somme(0) ? somme(-3) ? Que se passe-t-il dans le second cas et pourquoi ? (→ le cas de base n’est jamais atteint, récursion infinie : le test devrait être n <= 0)
  4. Tracez à la main l’exécution de somme(3) en notant chaque appel et chaque retour.
  5. Que se passe-t-il si on inverse les deux branches (else d’abord) ? Le code reste-t-il correct ?

Aller plus loin

  1. Transformez somme en fonction itérative (boucle for). Comparez : laquelle consomme le plus de mémoire ? (→ la récursive, à cause de la pile)
  2. Écrivez une fonction récursive puissance(x, n) puis fibo(n).
  3. fibo récursive naïve recalcule beaucoup de valeurs : quel est le problème ? (→ complexité exponentielle)
  4. Vrai/faux : une fonction récursive est toujours plus lente qu’une fonction itérative. (→ faux en général, mais souvent vraie en Python : pas d’optimisation de la récursion terminale)
