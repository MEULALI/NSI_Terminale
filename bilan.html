une pile, c’est comme une pile d’assiettes

  • On empile une assiette au sommet : empiler
  • On dépile : on retire toujours celle du sommet : depiler
  • On ne peut toucher qu’au dernier élément ajouté : c’est le principe LIFO (Last In, First Out — dernier entré, premier sorti).

Le lien avec les listes Python

Une liste Python fait très bien le travail :

Opération sur la pile

Avec une liste self.data

Empiler

self.data.append(x) — ajoute à la fin

Dépiler

self.data.pop() — retire et renvoie le dernier

Est vide ?

self.data == [] (ou len(self.data) == 0)

Le “sommet” de la pile correspond simplement au dernier élément de la liste.

une file, c’est comme une file d’attente

  • On enfile à l’arrière (enfiler)
  • On défile par l’avant (defiler) — le premier arrivé est le premier sorti : c’est le FIFO (First In, First Out).

C’est l’exact opposé de la pile (LIFO). Comme à la boulangerie : on se met derrière, et c’est celui qui attend depuis le plus longtemps qui est servi.

La nuance de performance

Opération Coût
append(x) (à la fin) constant — rapide, quel que soit la taille
pop(0) (au début) linéaire — il faut décaler tous les autres éléments d’une case vers la gauche

Image concrète : quand le premier client part, tout le monde dans la file avance d’un pas. Si la file a 10 000 éléments, Python fait 10 000 décalages. À la fin de la liste, rien ne bouge — c’est pour ça que la pile (append + pop()) est parfaite avec les listes, mais que la file est satisfaisante mais pas optimale.

on peut mesurer ça expérimentalement :

from time import time

f = File()
for i in range(100_000):
    f.enfiler(i)

debut = time()
while not f.est_vide():
    f.defiler()
print(time() - debut, "secondes")

Synthèse à retenir

  • Pile = LIFO : on entre et on sort par le même bout → append + pop()
  • File = FIFO : on entre par un bout, on sort par l’autre → append + pop(0)
  • La liste Python implémente parfaitement la pile, mais seulement correctement la file (pas en temps constant pour défiler).
