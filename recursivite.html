Fonctionnement d’un programme récursif

En bref — Les fonctions récursives permettent de simplifier l’écriture de nombreux problèmes. Nous présentons ici leur fonctionnement et une méthodologie d’écriture et d’analyse de ces fonctions.

I. Introduction à la récursivité

Une fonction récursive est une fonction qui s’appelle elle-même. Voici un premier exemple classique :

def expo(a, n):
    if n == 0:
        return 1
    else:
        return a * expo(a, n - 1)

Cette fonction implémente simplement une façon (récursive) de définir la puissance d’un nombre a>0a > 0a>0 : a0=1a^0 = 1a0=1 et an=a×an−1a^n = a \times a^{n-1}an=a×an−1.

On remarque que la fonction commence par une condition d’arrêt qui traite le cas de base.

MOT CLÉ
Un cas de base est une valeur de l’argument pour laquelle le problème se résout immédiatement.

Pour étudier le fonctionnement interne de cette fonction, on peut réécrire la fonction précédente :

def expo(a, n):
    if n == 0:
        print("On a n = 0")
        return 1
    else:
        print("On a n =", n)
        return a * expo(a, n - 1)

II. Pile d’exécution

Lors de l’appel d’une fonction récursive, une structure de pile est utilisée en interne.

Une pile fonctionne comme un empilement d’objets (l’image d’une pile d’assiettes est adaptée) : on peut empiler un objet en haut de la pile et enlever le sommet de la pile (on dit dépiler), mais on ne peut pas accéder à un objet qui n’est pas en haut de la pile.

La pile utilisée, appelée pile d’exécution, est de taille limitée. Au-delà d’un certain nombre d’appels récursifs (1000 par défaut en Python), il y a une erreur de dépassement de la taille de la pile (stack overflow). Cette pile contient une trace de tous les appels de fonction qui ne se sont pas encore terminés.

Concrètement, un appel récursif à expo(2, 3) donne, de manière très simplifiée :

  • expo(2, 3) = 2 * expo(2, 2)
  • expo(2, 2) = 2 * expo(2, 1)
  • expo(2, 1) = 2 * expo(2, 0)
  • expo(2, 0) = 1

Évolution de la pile d’exécution, puis dépilement pour évaluer :

expo(2,0)⟶1\text{expo}(2, 0) \longrightarrow 1expo(2,0)⟶1
2×expo(2,0)⟶2×1=22 \times \text{expo}(2, 0) \longrightarrow 2 \times 1 = 22×expo(2,0)⟶2×1=2
2×2×expo(2,0)⟶2×2=42 \times 2 \times \text{expo}(2, 0) \longrightarrow 2 \times 2 = 42×2×expo(2,0)⟶2×2=4
2×2×2×expo(2,0)⟶2×4=82 \times 2 \times 2 \times \text{expo}(2, 0) \longrightarrow 2 \times 4 = 82×2×2×expo(2,0)⟶2×4=8

III. Écriture d’une fonction récursive

Une fonction récursive simple s’écrit sous la forme :

def fun(args):
    if condition_d_arret:
        return valeur
    # appel récursif

Pour écrire une fonction récursive, on :

  1. Détermine le type de données à renvoyer ;
  2. Détermine pour quelle(s) valeur(s) de l’argument le problème est résolu et on écrit la condition d’arrêt ;
  3. Détermine de quelle manière la taille du problème est réduite (argument entier qui décroît strictement, liste dont la taille diminue, etc.) ;
  4. Écrit l’appel récursif en prenant garde à ce que le type de données qu’il renvoie soit cohérent avec celui renvoyé par la condition d’arrêt.

Exemples d’utilisation de la récursivité

En bref — Nous présentons ici quelques exemples d’utilisation de la récursivité et montrons tant la puissance des fonctions récursives que certains pièges que leur utilisation peut amener.

I. Recherche dichotomique dans une liste triée

Soit lst une liste de nombres triée dans l’ordre croissant et soit x un nombre.

Nous pouvons adapter l’algorithme de recherche dichotomique vu en Première de manière récursive : on teste si l’élément médian de lst est égal à x, sinon on cherche sa présence à gauche ou à droite dans lst suivant qu’il est plus grand ou plus petit que x.

Cet algorithme s’arrête lorsque lst est vide.

def recherche(lst, x):
    if len(lst) == 0:
        return False
    m = len(lst) // 2
    if lst[m] == x:
        return True
    elif lst[m] < x:
        return recherche(lst[m+1:], x)
    else:
        return recherche(lst[:m], x)

En apparence, cette fonction a la même complexité que la recherche dichotomique dans une liste triée écrite de manière itérative, donc de l’ordre de O(log⁡(n))\mathcal{O}(\log(n))O(log(n)). Néanmoins, le slicing (découpage de liste) a un coût caché qu’il faut prendre en compte.

La relation de récurrence s’écrit alors Tn=Tn/2+n/2T_n = T_{n/2} + n/2Tn​=Tn/2​+n/2. Cette relation mène à Tn=Θ(n)T_n = \Theta(n)Tn​=Θ(n).

MOT CLÉ
Une fonction locale est une fonction définie à l’intérieur d’une fonction. Elle permet, notamment dans le cadre de la récursivité, d’ajouter des arguments à une fonction.

L’utilisation d’une fonction locale stockant les indices gauches et droits encadrant les indices où peut être trouvé l’élément aurait permis de réduire cette complexité :

def recherche2(lst, x):
    def rec(i, j, x):
        if i > j:
            return False
        m = (i + j) // 2
        if lst[m] == x:
            return True
        elif lst[m] < x:
            return rec(m + 1, j, x)
        else:
            return rec(i, m - 1, x)
            
    return rec(0, len(lst) - 1, x)

La fonction recherche2 n’effectue que des opérations élémentaires à chaque appel récursif. Le fait d’utiliser comme arguments supplémentaires les indices iii et jjj tels que lst[i]≤x≤lst[j]\text{lst}[i] \le x \le \text{lst}[j]lst[i]≤x≤lst[j] permet d’éviter d’effectuer des opérations directement sur la liste et réduit le coût.

Ceci a comme coût Tn=Tn/2+1T_n = T_{n/2} + 1Tn​=Tn/2​+1, ce qui mène à Tn=Θ(log⁡(n))T_n = \Theta(\log(n))Tn​=Θ(log(n)).

II. Suite de Fibonacci et récursivité explosive

1. Fonction récursive naïve de Fibonacci

On s’intéresse ici à la programmation récursive du calcul du terme général de la suite de Fibonacci, définie par :
u0=0,u1=1et pour tout n∈N,un+2=un+1+unu_0 = 0,\quad u_1 = 1 \quad \text{et pour tout } n \in \mathbb{N},\quad u_{n+2} = u_{n+1} + u_nu0​=0,u1​=1et pour tout n∈N,un+2​=un+1​+un​

Une écriture naïve de ce calcul conduit à :

def fibo(n):
    if n < 2:
        return n
    return fibo(n - 1) + fibo(n - 2)

Si cette fonction renvoie le bon résultat, les valeurs un tant soit peu élevées de nnn donnent des calculs très longs (essayer fibo(37)).

Une analyse de complexité explique ce temps de calcul. Si TnT_nTn​ désigne le nombre d’opérations pour calculer fibo(n), on obtient la relation de récurrence Tn+2=Tn+1+Tn+1T_{n+2} = T_{n+1} + T_n + 1Tn+2​=Tn+1​+Tn​+1. Or cette suite croît encore plus vite que la suite de Fibonacci elle-même, qui a déjà un comportement exponentiel.

2. Fonction récursive avec mémoïsation

Une solution possible consiste à garder en mémoire les termes de la suite déjà calculés. Cette technique de mémoïsation (procédé où l’on garde en mémoire les valeurs déjà calculées) peut par exemple être traitée en créant un dictionnaire qui stocke ces valeurs, ainsi qu’une fonction locale :

def fibo(n):
    memo_fibo = dict()
    def fib(n):
        if n in memo_fibo:
            return memo_fibo[n]
        if n < 2:
            memo_fibo[n] = n
        else:
            memo_fibo[n] = fib(n - 1) + fib(n - 2)
        return memo_fibo[n]
    return fib(n)
