Structures de données

1. Interface et implémentation

Le langage Python dispose, comme tous les langages de haut niveau, d’un ensemble de types de base et de types structurés vus dans le programme de Première : nombres, chaînes de caractères, tuples, tableaux, dictionnaires. Ces types sont des briques de base qui permettent de créer des structures de données plus complexes. Pour définir ces structures de données, on utilise des types abstraits de données.

Un type abstrait est caractérisé par une interface de programmation, c’est-à-dire un ensemble d’opérations qui permettent de manipuler les données de ce type. On distingue :

  • les constructeurs, qui permettent de créer une nouvelle structure de données ;
  • les opérateurs, qui permettent de modifier la structure de données, par exemple en ajoutant ou retirant des données ;
  • les accesseurs, qui donnent de l’information sur la structure de données, comme son nombre d’éléments ;
  • les itérateurs, qui permettent d’énumérer les éléments de la structure de données.

Spécifier un type abstrait, c’est définir son interface, sans préjuger de la façon dont ses opérations seront implémentées. Implémenter un type abstrait, c’est fournir le code de ces opérations en utilisant des types existants. Plusieurs implémentations peuvent répondre à la même spécification. Le programmeur peut alors choisir celle qui lui convient le mieux. Certaines implémentations peuvent être plus ou moins rapides, plus ou moins économes en mémoire ou plus ou moins adaptées à des données de grande taille.

En séparant la spécification de l’implémentation, il est plus facile de diviser le travail des programmeurs et d’organiser la structure générale du programme. Certains types abstraits très souvent utilisés, comme ceux présentés dans ce chapitre, sont également disponibles dans des bibliothèques logicielles. Il suffit alors de connaître leur interface pour les utiliser, sans avoir à entrer dans les détails de leur implémentation.

Les quatre types abstraits présentés dans ce chapitre sont utilisés très fréquemment dans toutes sortes de programmes. Ils servent aussi de base à d’autres types abstraits. Nous verrons ainsi qu’une file peut être implémentée avec deux piles, elles-mêmes implémentées par des listes, ou qu’un dictionnaire peut être implémenté avec des listes.

Les implémentations présentées dans ce chapitre utilisent un style de programmation fonctionnelle : les opérations sont des fonctions qui prennent la structure de données en paramètre et, pour les constructeurs et opérateurs, retournent la structure résultant de l’opération. Le chapitre suivant présentera des implémentations utilisant un style de programmation par objets.

NOTE : Un type abstrait est un type car il définit les opérations possibles sur la structure de données. Il est abstrait car on ne détaille pas son implémentation.

NOTE : On utilise souvent le terme de structure de données abstraite à la place de type abstrait. Les types structurés du langage sont souvent appelés structures de données concrètes ou types concrets.

2. Les listes

Une liste est une séquence ordonnée d’éléments. Son interface minimale est la suivante :

  • creer_liste() : constructeur qui retourne une liste vide ;
  • liste_vide(l) : accesseur qui retourne Vrai si la liste l est vide ;
  • inserer(l, e) : opérateur qui insère e en tête de liste et retourne la nouvelle liste ;
  • tete(l) : accesseur qui retourne l’élément en tête de liste (si celle-ci n’est pas vide) ;
  • queue(l) : accesseur qui retourne la liste privée de son premier élément (si la liste n’est pas vide) ;
  • elements_liste(l) : itérateur qui retourne un tableau contenant les éléments de la liste, que l’on peut ensuite énumérer avec une boucle for.

2.1. Implémentation par des tuples

On peut implémenter une liste en Python en utilisant des tuples. Comme les tuples Python sont immuables, la liste elle-même sera immuable, ce qui peut être intéressant dans certains cas.

Une liste est représentée par un tuple (tete, queue) où tete est le premier élément de la liste et queue est le reste de la liste, qui est elle-même une liste (donc un tuple).

L’implémentation est très simple :

def creer_liste():
    return ()    # la liste vide est le tuple vide

def liste_vide(liste):
    return liste is ()    # la liste est vide si c'est le tuple vide

def inserer(liste, element):
    return (element, liste)    # nouvelle liste = tuple avec l'élément en tête

def tete(liste):
    assert not liste_vide(liste), "tete : liste vide !"
    element, _ = liste    # la tête de liste est le 1er élément du tuple
    return element

def queue(liste):
    assert not liste_vide(liste), "queue : liste vide !"
    _, reste = liste    # la queue de liste est le 2e élément du tuple
    return reste

def elements_liste(liste):
    res = []    # le tableau résultat
    while liste is not ():    # à chaque itération :
        tete, liste = liste    # extraire l'élément et la nouvelle liste
        res.append(tete)    # ajouter l'élément au résultat
    return res    # retourner le résultat
On peut utiliser la liste de la manière suivante :

```python

liste = creer_liste()
liste = inserer(liste, "Alice")
liste = inserer(liste, "Bob")
liste = inserer(liste, "Charlie")
elem = tete(liste)       # elem vaut "Charlie"
reste = queue(liste)     # reste est la liste ("Bob", "Alice")
liste_vide(liste)        # False
for e in elements_liste(liste):
    print(e)    # Charlie Bob Alice

L’état de la liste après la ligne 4 est ("Charlie", ("Bob", ("Alice", ()))). Conventionnellement, on représente les listes par une chaîne de maillons reliés par des flèches :

2.2. Implémentation par un tableau

Une autre implémentation possible d’une liste consiste à utiliser un tableau. La liste est alors représentée par un tuple constitué du tableau et du nombre d’éléments de la liste. La représentation de la liste de l’exemple précédent avec un tableau de taille 5 est alors la suivante :

liste = (["Charlie", "Bob", "Alice", None, None], 3)

Le tableau ayant une taille fixe, il faut prévoir que la capacité de la liste est limitée à la taille du tableau. Il est aussi possible de créer un tableau plus grand et d’y recopier la liste lorsque nécessaire. Dans ce cas, on peut vouloir recopier la liste dans un tableau plus petit lorsque la taille de la liste devient trop petite.

NOTE Les tableaux Python sont en réalité des listes puisqu’ils sont extensibles avec la méthode append.

2.3. Étendre l’interface

On peut enrichir l’interface d’une liste de plusieurs opérations :

  • taille(l) : accesseur qui retourne le nombre d’éléments de la liste ;

  • ième(l, i) : accesseur qui retourne le iii-ème élément de la liste ;

  • ajouter_fin(l, e) : opérateur qui ajoute eee à la fin de la liste ;

  • insérer_ième(l, i, e) : opérateur qui insère l’élément eee en iii-ème position ;

  • remplacer(l, i, e) : opérateur qui remplace le iii-ème élément par eee ;

  • supprimer_ième(l, i) : opérateur qui supprime le iii-ème élément de la liste.

Dans l’implémentation avec les tuples, les opérateurs ci-dessus sont coûteux à réaliser car les tuples sont immuables et il faut donc créer une nouvelle liste complète.

3. Les Piles

Une pile est un ensemble ordonné d’éléments qui se comporte comme une pile d’assiettes : on peut ajouter une assiette sur la pile ou prendre l’assiette sur le dessus de la pile.

Son interface minimale est la suivante :

  • creer_pile() : constructeur qui retourne une pile vide ;

  • pile_vide(p) : accesseur qui retourne Vrai si la pile ppp est vide ;

  • empiler(p, e) : opérateur qui ajoute eee au sommet de la pile ppp ;

  • dépiler(p) : opérateur qui retire l’élément en sommet de pile (si elle n’est pas vide) et retourne la nouvelle pile ;

  • sommet(p) : accesseur qui retourne le sommet de la pile (si elle n’est pas vide) ;

  • elements_pile(p) : itérateur qui énumère les éléments de la pile.

3.1. Implémentation par une liste

Une liste permet d’implémenter une pile de façon quasiment immédiate puisque les opérations insérer(), tête() et queue() correspondent respectivement à empiler(), sommet() et dépiler().

3.2. Implémentation par un tableau

Une autre implémentation consiste à utiliser un tableau. De façon similaire à l’implémentation d’une liste par un tableau, on utilise un tuple contenant le tableau lui-même et le nombre d’éléments dans la pile, qui est aussi l’indice auquel sera ajouté le prochain élément.

Comme un tableau a une taille limitée, on spécifie la capacité maximale de la pile à sa création et une opération d’accès pour tester si la pile est pleine :

  • creer_pile(n) : constructeur qui retourne une pile vide, de capacité nnn éléments ;

  • pile_pleine(p) : accesseur qui retourne Vrai si la pile ppp est pleine.

def creer_pile(n):
    # une pile vide est un tuple formé d'un tableau de n éléments et d'une taille de 0
    return ([None] * n, 0)

def pile_vide(pile):
    t, top = pile
    return top == 0  # la pile est vide si sa taille est 0

def pile_pleine(pile):
    t, top = pile
    return top == len(t)  # la pile est pleine si sa taille atteint sa capacité

def empiler(pile, element):
    assert not pile_pleine(pile), "empiler : pile pleine !"
    t, top = pile
    t[top] = element  # on ajoute l'élément au bout du tableau
    return (t, top + 1)  # on retourne la nouvelle pile

def depiler(pile):
    assert not pile_vide(pile), "depiler : pile vide !"
    t, top = pile
    return (t, top - 1)  # on retourne la nouvelle pile

def sommet(pile):
    assert not pile_vide(pile), "sommet : pile vide !"
    t, top = pile
    return t[top - 1]  # Le sommet est en dessous de l'indice top

def elements_pile(pile):
    res = []  # le tableau résultat
    t, top = pile  # récupérer le tableau et la taille
    for i in range(top, 0, -1):  # on parcourt du sommet vers la base (i va de top à 1)
        res.append(t[i - 1])
    return res  # on retourne le tableau résultat

NOTE Comme pour l’implémentation d’une liste par un tableau, on peut lever cette contrainte en recopiant la pile dans un tableau plus grand lorsqu’elle est pleine.

NOTE Cette implémentation utilise un tableau ttt dont on modifie le contenu, ce qui peut créer des problèmes d’aliasing (exercice 22). Pour les éviter, il faut toujours affecter la valeur de retour d’un opérateur qui modifie la structure de données à la même variable que celle passée en paramètre, par exemple : p = depiler(p).

On peut utiliser la pile de la manière suivante :

pile = creer_pile(10)
pile = empiler(pile, "Alice")
pile = empiler(pile, "Bob")
pile = empiler(pile, "Charlie")
elem = sommet(pile)           # elem vaut "Charlie"
pile = depiler(pile)          # la pile a 2 éléments
pile_vide(pile)              # False
for e in elements_pile(pile):
    print(e)                  # Bob Alice

NOTE La différence entre une liste et une pile est que l’on ne définit pas d’opérateurs supplémentaires tels que insérer_ième ou remplacer.

NOTE Après l’appel à depiler (dernière étape), "Charlie" est toujours dans le tableau mais ne fait plus partie de la pile. Il sera écrasé par le prochain empiler.

L’état du tableau représentant la pile après chacune des lignes 1 à 4 et après la ligne 6 est le suivant :

  • Ligne 1 : top = 0 →\rightarrow→ [None, None, ...]

  • Ligne 2 : top = 1 →\rightarrow→ ["Alice", None, ...]

  • Ligne 3 : top = 2 →\rightarrow→ ["Alice", "Bob", None, ...]

  • Ligne 4 : top = 3 →\rightarrow→ ["Alice", "Bob", "Charlie", None, ...]

  • Ligne 6 : top = 2 →\rightarrow→ ["Alice", "Bob", "Charlie", None, ...] (Charlie est conservé en mémoire tampon mais le sommet logique est remis à l’indice 2)

4. Liste FIFO (les files)

Une file est un ensemble ordonné d’éléments qui se comporte comme une file d’attente : un nouvel arrivant se met à la fin de la file, tandis que la prochaine personne servie est celle en tête de file.

La différence avec une pile est que :

  • dans une pile, le dernier arrivé est le premier servi — on parle d’une liste LIFO : Last In, First Out ;
  • dans une file, le premier arrivé est le premier servi — on parle d’une liste FIFO : First In, First Out.

L’interface minimale d’une file est la suivante :

  • creer_file() : constructeur qui retourne une file vide ;
  • file_vide(f) : accesseur qui retourne Vrai si la file f est vide ;
  • enfiler(f, e) : opérateur qui ajoute e à la fin de la file f ;
  • defiler(f) : opérateur qui retire l’élément en début de file (si elle n’est pas vide) ;
  • tete_file(f) : accesseur qui retourne le premier élément de la file (si elle n’est pas vide) ;
  • elements_file(f) : itérateur qui énumère les éléments de la file.

4.1. Implémentation par un tableau

Comme la pile et la liste, on peut implémenter une file avec un tableau, en lui donnant une capacité limitée. Comme pour la pile, on représente la file par un tuple (tableau, taille) et on ajoute les éléments à l’indice taille (sauf si le tableau est plein). Contrairement à la pile, on doit retirer les éléments au début du tableau.

Une solution simple est de décaler les éléments du tableau :

def defiler(file):
    assert not file_vide(file), "defiler : file vide !"
    t, taille = file
    taille -= 1    # la file a un élément de moins
    for i in range(taille):    # on décale les éléments d'un cran vers la gauche
        t[i] = t[i+1]
    return (t, taille)    # on retourne la nouvelle file

NOTE : Comme pour l’implémentation de la pile par un tableau, il faut soit prévoir une capacité maximale, soit recopier le tableau dans un tableau plus grand lorsque la file est pleine.

NOTE : Après le décalage, le dernier élément (« Charlie ») est répété deux fois, mais seule la première occurrence appartient à la file.

4.2. Implémentation par un tableau circulaire

L’implémentation précédente est coûteuse si la file est grande puisqu’à chaque retrait, il faut recopier tous les éléments restants. Une implémentation plus efficace consiste à considérer le tableau comme un anneau dont la file occupe les éléments de l’indice debut à l’indice fin - 1.

On ajoute les éléments à l’indice fin, comme pour une pile, mais lorsqu’on arrive à la fin du tableau, on continue à remplir au début (si le tableau n’est pas plein). Similairement, on retire les éléments à l’indice debut, et lorsque celui-ci arrive à la fin du tableau, on le replace au début.

Ainsi, après plusieurs ajouts et retraits, les éléments de la file occupent la fin du tableau puis le début de celui-ci, comme illustré ci-dessous (les éléments verts appartiennent à la file : e1, e2, e3, e4) :

Une autre implémentation d’une file consiste à utiliser deux piles, entree et sortie :

  • on ajoute les éléments sur la pile entree ;
  • on les retire de la pile sortie ;
  • si la pile sortie est vide, on y transfère les éléments de la pile entree.

On voit qu’à toutes les étapes, les éléments sont dans l’ordre de leur arrivée.

L’avantage de cette méthode est que si l’on utilise l’implémentation des piles entree et sortie par des tuples, on obtient une file sans limitation de capacité.

5. Les dictionnaire

Un dictionnaire associe des clés à des valeurs, de même qu’un dictionnaire français-anglais, par exemple, associe à chaque mot sa traduction.

L’interface minimale d’un dictionnaire est la suivante :

  • creer_dico() : constructeur qui retourne un dictionnaire vide ;
  • ajouter(d, cle, valeur) : opérateur qui ajoute cle au dictionnaire et l’associe à valeur ;
  • valeur_cle(d, cle) : accesseur qui retourne la valeur associée à cle, si elle est présente ;
  • cles_dico(d) : itérateur qui énumère les clés du dictionnaire.

Le langage Python fournit directement le type structuré dict qui implémente un dictionnaire :

  • creer_dico() : d = dict() ou d = {}
  • ajouter(d, cle, valeur) : d[cle] = valeur
  • valeur_cle(d, cle) : d[cle]
  • cles_dico(d) : for cle in d:

Il n’y a donc pas d’intérêt particulier à fournir une autre implémentation, sauf éventuellement dans des cas particuliers où les performances ne seraient pas satisfaisantes.

5.1. Implémentation par une liste

Hormis l’utilisation directe du dict Python, une implémentation simple consiste à créer une liste de tuples (cle, valeur). L’ajout d’une nouvelle entrée se fait au début et la recherche d’une clé se fait en parcourant la liste.

Cette méthode est peu efficace lorsque la taille du dictionnaire augmente. Elle peut être améliorée s’il existe un ordre sur les clés, en utilisant un tableau classé par ordre croissant de clé et une recherche dichotomique.

L’implémentation est laissée à titre d’exercices (n° 12 et 33).

5.2. Implémentation par une table de hachage

Une implémentation plus efficace consiste à utiliser un tableau et à transformer la clé en un indice dans le tableau grâce à une fonction de hachage. Par exemple, si l’on considère des clés qui sont des chaînes de caractères, une fonction de hachage peut consister à ajouter les codes de chaque caractère, modulo la taille du tableau :

HTAILLE = 189    # taille des tables de hachage

def hachage(cle):
    code = 0
    for car in cle:
        code += ord(car)
    return code % HTAILLE

Cela permet de trouver directement l’emplacement d’une clé dans le tableau, sans avoir besoin de le parcourir. Il suffit alors de stocker la valeur associée à la clé à cet indice du tableau.

Cependant, il est possible que deux clés différentes aient le même code de hachage. On appelle cela une collision. Il existe plusieurs méthodes pour traiter les collisions.

La méthode illustrée ci-dessous consiste à stocker dans chaque élément de la table, t[h], une liste des paires (cle, valeur) qui ont même code de hachage h. Une implémentation est la suivante :

def creer_dico():
    return [None] * HTAILLE    # tableau de HTAILLE éléments

def ajouter_cle(dico, cle, valeur):
    h = hachage(cle)    # calculer le code de hachage de la clé
    if dico[h] is None:    # si l'entrée du dictionnaire est vide
        dico[h] = creer_liste()    # l'initialiser avec une liste vide
    # insérer la paire (cle, valeur) en tête de la liste des collisions
    dico[h] = inserer(dico[h], (cle, valeur))
    return dico

def valeur_cle(dico, cle):
    h = hachage(cle)    # calculer le code de hachage de la clé
    if dico[h] is None:    # si l'entrée du dictionnaire est vide
        return None    # None indique que la clé n'est pas présente
    for c, v in elements_liste(dico[h]):    # parcourir la liste des collisions
        if cle == c:    # si la clé correspond
            return v    # retourner la valeur
    return None    # sinon la clé n'est pas dans le dictionnaire

def cles_dico(dico):
    t = []    # tableau des clés
    for liste in dico:    # pour chaque élément du tableau
        if liste is not None:    # s'il n'est pas vide
            for cle, _ in elements_liste(liste):    # parcourir les collisions
                t.append(cle)    # ajouter la clé
    return t    # retourner le tableau des clés

On peut utiliser le dictionnaire de la manière suivante :

dico = creer_dico()
dico = ajouter_cle(dico, "Alice", 1234)
dico = ajouter_cle(dico, "Bob", 246)
dico = ajouter_cle(dico, "Charlie", 357)

valeur_cle(dico, "Bob")     # 246
valeur_cle(dico, "Danny")   # None car la clé n'est pas dans dico

for cle in cles_dico(dico):
    print(cle, valeur_cle(dico, cle))
    # "Bob" 246, "Alice" 1234, "Charlie" 357

5.3. Étendre l’interface

On peut étendre l’interface d’un dictionnaire en autorisant le changement d’une valeur associée à une clé et le retrait d’une clé :

  • cle_presente(d, cle) : accesseur qui retourne Vrai si la clé est dans le dictionnaire ;
  • changer_valeur(d, cle, valeur) : opérateur qui remplace la valeur de la clé, si elle existe ;
  • retirer_cle(d, cle) : opérateur qui retire la clé du dictionnaire, si elle existe.

En Python, ces opérations sont directement accessibles :

  • cle_presente(d, cle) : cle in d
  • changer_valeur(d, cle, valeur) : d[cle] = valeur
  • retirer_cle(d, cle) : del d[cle]

Dans l’implémentation par table de hachage illustrée plus haut, comme les listes de collisions sont immuables, il faut recréer la nouvelle liste de collisions après avoir changé la valeur ou retiré la clé.
